## Options and Trade-offs

- **Option A (recommended) — Page-scoped DOM restructure + new `.page-head-top` class:** Minimal blast radius (one template + additive CSS), makes the single-row intent explicit instead of depending on `space-between` between unequal-height columns, and cannot regress the other three pages using `.page-head`.
- **Option B — Redefine `.page-head` globally** into a two-tier contract and migrate all four pages: consistent long-term, but exceeds the stated scope, triples regression surface (projects list, results, templates), and requires coordinated template edits elsewhere.
- **Option C — Scoped `<style>` in the SFC only:** avoids touching `main.scss`, but fragments header styling across two locations while `main.scss` already owns `.page-head`/`.head-actions` conventions; risks specificity fights with the global mobile rules at `main.scss:1124`.
