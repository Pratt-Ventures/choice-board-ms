## Summary

Restructure the header of `client/pages/projects/[id]/index.vue` so one explicit top row holds the "← Projects" back link (left) and the action buttons (right-floated), vertically centered against each other, with the project title, description, and status chips moved below that row. This is a layout-only change: all labels, variants, icons, handlers, routes, visibility conditions (`v-if="!inputClosed"`, `canRunAiAgents && !inputClosed`), and the `summary-hero` content stay untouched.

**Key findings from code inspection:**
- Current DOM (`client/pages/projects/[id]/index.vue:5-59`): `.page-head` is a flex container (`justify-content: space-between`) whose first child bundles back link + title + subtitle + status chips, with a sibling `.head-actions` holding six buttons in order: **Project settings → Make a copy → Invite people → Start comparing (conditional) → View results → Run AI agents (conditional)**.
- Styles live globally in `client/assets/styles/main.scss:251-265` (`.page-head`, `.head-actions`) with a mobile override at `main.scss:1124-1125` (`<960px`: `.page-head { display:block }`, `.head-actions { margin-top:14px }`).
- `.page-head`/`.head-actions` are shared by three other pages (`client/pages/projects/index.vue`, `client/pages/projects/[id]/results.vue`, `client/pages/templates/index.vue`) — global style semantics must not change for them.
- E2E coverage is one spec (`e2e/tests/share-access-modes.spec.ts`) that does not reference any header buttons or selectors, so test impact is expected to be zero.
- No lint/typecheck scripts exist in `client/package.json` (only `dev`/`build`/`generate`/`preview`); verification will be via dev server visual checks and the Playwright suite.

## Implementation Steps

1. **Restructure the template** (`client/pages/projects/[id]/index.vue:5-59`): introduce a top row wrapper `<div class="page-head-top">` as the first child of `.page-head`, containing (a) the existing back-link `v-btn` ("← Projects", `:to="'/projects'"`, unchanged props/classes minus its layout-only `mb-1` if needed for alignment) and (b) the existing `.head-actions` div relocated into this row.
2. **Move the title block down**: place the existing `.page-title` / `.page-subtitle` / status-chip markup in its own block directly below `.page-head-top`, still inside `.page-head`, byte-for-byte identical otherwise.
3. **Preserve the action bar exactly**: keep all six buttons in their current DOM order inside `.head-actions` — including conditional `Start comparing` and `Run AI agents` — with identical variants, icons, click handlers, `:to` targets, and `v-if`s.
4. **Add scoped-to-new-class styles** in `client/assets/styles/main.scss` next to the existing `.page-head` block (~line 251): `.page-head-top { display:flex; align-items:center; justify-content:space-between; gap:12px; flex-wrap:wrap; row-gap:10px; width:100%; }` plus small spacing between the top row and title block. Do **not** modify the meaning of `.page-head`/`.head-actions` used by the other three pages.
5. **Responsive behavior**: rely on `flex-wrap` on `.page-head-top` so at <960px the action group wraps beneath the back link instead of overlapping it; audit the media query at `main.scss:1124-1125` and adjust only if the legacy `.page-head { display:block }` / `.head-actions { margin-top:14px }` rules conflict (e.g., replace the latter with a `row-gap`-based rule that applies to the new row). Confirm the four named buttons read left-to-right when wrapped.
6. **Verify**:
   - Run the client dev server and inspect `/projects/{id}` at desktop width (>960px): back link top-left, buttons top-right, vertically centered on the same line, order preserved; confirm title/description/chips render below unchanged.
   - Narrow viewport (<960px, ~768px and ~400px): buttons wrap under the back link with no overlap/clipping.
   - Spot-check the three sibling pages sharing `.page-head` (projects list, project results, templates) for regressions.
   - Run the e2e suite (`cd e2e && npm test`) to confirm no breakage; no selector updates anticipated since nothing references the header.

## Options and Trade-offs

- **Option A (recommended) — Page-scoped DOM restructure + new `.page-head-top` class:** Minimal blast radius (one template + additive CSS), makes the single-row intent explicit instead of depending on `space-between` between unequal-height columns, and cannot regress the other three pages using `.page-head`.
- **Option B — Redefine `.page-head` globally** into a two-tier contract and migrate all four pages: consistent long-term, but exceeds the stated scope, triples regression surface (projects list, results, templates), and requires coordinated template edits elsewhere.
- **Option C — Scoped `<style>` in the SFC only:** avoids touching `main.scss`, but fragments header styling across two locations while `main.scss` already owns `.page-head`/`.head-actions` conventions; risks specificity fights with the global mobile rules at `main.scss:1124`.

Sub-decision — which buttons move: relocating only the four named buttons would orphan "Project settings" and "Run AI agents" in a lower/secondary position and visually split one logical action bar; moving the whole bar keeps every control together and still preserves the required left-to-right order of the named four.
