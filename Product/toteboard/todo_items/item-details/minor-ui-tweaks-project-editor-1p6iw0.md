## Plan: Minor UI Tweaks – Project Editor

### 1) Implementation steps

1. **Ranking-mode toggle (edit settings)** — `client/pages/projects/[id]/edit.vue`
   - Remove the `Find Top Half` button (line 95) from the Decision-mode `v-btn-toggle`; relabel `Rank All` → `Rank Entire Options List` (line 96).
   - Drop/replace the `find_top_half` hint branch in `rankingModeHint` (lines 864–869).
   - Legacy fallback: keep `find_top_half` as a valid stored value (load mapping at lines 1255–1258 unchanged). If a loaded project is already `find_top_half`, render that toggle entry disabled/badged "legacy mode" instead of silently hiding it, so the current selection stays visible and users can switch away; save sends whatever is selected — no auto-migration.
2. **Mode nomenclature on status surfaces** — update `'Rank all'` → `'Rank Entire Options List'` (keep `'Pick one'`): overview chip + summary hero `client/pages/projects/[id]/index.vue:22,66`; edit review-tab chip `edit.vue:474`; template-save copy `edit.vue:578`. Optionally add a shared `modeLabel()` helper in `client/utils/ranking.ts` to replace the repeated ternaries.
3. **Confidence bar legend** — `client/components/RankingConfidenceBar.vue`: caption line 12 → "Your Current Ranking Confidence"; update matching aria-label (line 9). Both consumers (`probe.vue:58`, `ShareVoteSession.vue:143`) pick this up automatically.
4. **Group interstitial reorder** — `client/components/CompareQuestionHeader.vue` (intro variant only): move the criterion banner above the kicker/question block so order becomes title → description → question; render description inline when present (already available via `factorDetailsCopy()` from `criterion.description`, currently dialog-only); keep description omitted when empty. Leave `variant="pair"` rendering untouched. Consumers needing no change: `probe.vue:129-142`, `ShareVoteSession.vue:202-215`.
5. **Adaptive Start/Continue Comparing** — `client/pages/projects/[id]/index.vue`: add computed `myObservationCount > 0 ? 'Continue comparing' : 'Start comparing'` bound to the head-action button (line 43). `my_observation_count` (server: `src/api/app_customer_project_management.py:576,624`) is per logged-in user and includes partial-flushed votes, satisfying "even partial counts"; no API change needed. The "Recommended next action" card already routes repeat users to results, so no change there.
6. **Verification** — grep repo for stale strings (`Rank All`, `Start Comparing` as fixed labels, `Current ranking confidence`); run client unit tests (`node --test client/utils/*.test.ts` — none assert changed labels today) and the Playwright suite in `e2e/` (no specs assert these labels; only the generic 'Comparing' eyebrow in `e2e/helpers/gate.ts:66`); manually exercise edit → review → overview → probe intro and one share/vote session.

### 2) Clarifying questions

1. Scope of "project status": include the projects-list rows (`client/pages/projects/index.vue:102,157,200`) and templates page ("Rank all options", `templates/index.vue:90`), or strictly settings + project overview?
2. For legacy `find_top_half` projects, is hidden-but-preserved (with a small "legacy mode" indicator when editing) acceptable, versus silently remapping them to another mode?
3. When input is closed, the compare button is hidden entirely — confirm closed-input users never see "Continue Comparing" (per the open question in the brief).

### 3) Options & trade-offs

- **Hide vs. remove top-half mode**: hard-delete the option/button everywhere is cleaner but breaks display for saved projects; **recommended**: hide for new selection + preserve value with legacy indicator (matches expanded note that `find_top_half` remains internally valid).
- **Deduplicate mode labels via shared helper vs. inline ternaries**: helper adds a tiny abstraction but prevents future drift across ~7 call sites; recommended given the rename touches many files.
- **Per-user detection source**: reuse summary's `my_observation_count` (zero backend work, already partial-inclusive) vs. new endpoint/share-session-aware check; recommended reuse — share participants use the share flow, not the customer overview, so logged-in identity suffices.
- **Interstitial reorder location**: change inside `CompareQuestionHeader` (one component, both probe and share flows consistent) vs. reordering in each page; recommended component-level change scoped to `variant === 'intro'`.
