Server-side AI is gated by new system config (service, access key, model; start with OpenCode GO/Zen). Keys and model details never reach the client; BYOK comes later. Two features: suggest/prefill factors from a problem title and description (user edits after), and one AI participant that answers up to the project’s max groups via concise prompts in grouping- and information-gain–biased random order, collected as extra groups with special status for an AI baseline.

- Scope: system config + server orchestration; factor suggest; single AI participant vs max groups; OpenCode GO/Zen first.
- Keys/model stay server-only; no client AI endpoints in this phase.
- Factor flow: invoke after title+description; prefill; user deletes/adjusts.
- Participant flow: same prompt sequencing as humans; responses tagged as AI baseline.
- Open: config schema/enable flag, prompt templates, grouping/order algorithm, rate limits/failures, how extra groups and special status appear in results.
