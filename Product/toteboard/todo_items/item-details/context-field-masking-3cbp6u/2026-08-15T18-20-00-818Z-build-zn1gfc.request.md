## 3. Options and trade-offs

| Topic | Options | Recommendation |
|---|---|---|
| Parse site | Inline `environ.get(...).split(',')` vs `field_validator` like SendGrid | **Validator + helper.** Empty/`None` → `[]`; unset → `["stripe_settings"]`; pydantic-settings will not JSON-parse a bare name. |
| Mask action | Drop key vs set `None` vs `"***"` | **Drop.** Matches “strip”; `null` still advertises the field. Frontend `CustomerRecord` does not use `stripe_settings`. |
| Where to apply | Copy+mutate models vs wrap serializer vs change types to `dict` | **Wrap serializer (or dump/pop).** Avoids ORM writes; keeps OpenAPI. Type→`dict` is simpler but loses schema. |
| Depth | Top-level only vs dotted paths | **Top-level only.** Default target is `Customer.stripe_settings`, a string column. |
| Missing fields | No-op vs log | **No-op.** Logging every context call is noise. |

**Out of scope:** other endpoints that return `User`/`Customer`; mutating stored rows; frontend type changes.
